SUMMARY
-------
8 distinct form components. Every one posts to the SAME endpoint:

    POST /api/contact        ->  src/pages/api/contact.js

That route does three things for each submission:
    1. Emails the team         (SMTP via nodemailer, to TO_EMAIL)
    2. Emails the sender       (acknowledgement — only if an email was given)
    3. Forwards to the CRM     (POST <INQUIRES_API_URL>/user/inquires,
                                best-effort, failure is logged not fatal)

There is NO second endpoint, no Formspree, no mailto anywhere.

Required env vars (all present in .env):
    SMTP_HOST  SMTP_PORT  SMTP_SECURE  SMTP_USER  SMTP_PASS
    FROM_EMAIL  TO_EMAIL
    NEXT_PUBLIC_BASE_INQUIRES_API_URL   (CRM forward; optional)

THINGS WORTH KNOWING
================================================================================
* "company" IS THE HONEYPOT.
  /api/contact treats any request with a non-empty "company" field as a bot and
  silently returns 200 WITHOUT sending mail. The real company name must be sent
  as "companyName" (HireBrief, app-development) or inside "subject"
  (home page, LeadForm). Get this wrong on a new form and every lead vanishes
  with no error.

* Rate limit: 20 submissions per IP per 15 minutes -> HTTP 429.
  All forms show "Too many requests. Please try again in a few minutes."

* Acknowledgement mail is skipped when no email address was given, so the
  phone-only path on /app-development still reaches the team.

* If SMTP fails, the API falls back to the CRM. If the CRM also fails it logs
  "[lead] LOST ENQUIRY" with the full payload and returns 502.

* CRM note: leads with no email are currently rejected by the CRM with HTTP 400
  ("[lead] CRM responded 400"). Mail still goes out, but those leads do not
  land in the CRM.

OPEN ISSUES FOUND WHILE TESTING
================================================================================
A. TWO PAGES RENDER BLANK (not a form bug — the forms on them still submit)
     /fully-manage-seo-services
     /graphic-design-company
   Both return 200 but with no H1, no content and the generic title
   "Mariox Software".

   Cause: src/pages/[serviceCity].jsx matches the URL with localServiceAt()
   (which matches on `href`) but then calls codedServiceProps(local.slug)
   (which matches on `/<slug>`). For entries whose href differs from their
   slug the second lookup misses and returns null, so the page falls through
   to an empty ServiceCityPage.
       fully-managed-seo-services -> href /fully-manage-seo-services
       graphic-design             -> href /graphic-design-company

   Fix (src/data/serviceAdapters.js, codedServiceProps):
       match on either the URL or the slug, and use the URL as the page slug.

B. CRM FORWARD REJECTS SOME LEADS (mail is unaffected)
   "[lead] CRM responded 400" appears when a lead has no email OR no phone.
   The newsletter signup (no phone) is rejected every time. The team still
   gets the email; only the CRM copy is missing.

C. DEAD CODE
   src/components/ServiceCityPage.jsx is now unreachable. After the service
   pages were unified, every branch of [serviceCity].jsx either renders
   ServiceDetail or TopCompanies, so ServiceCityPage (and the 2 ContactForm
   instances plus the ContactModal inside it) never render — except in the
   broken case in issue A above.
   src/components/LeadForm.jsx and MarketingLanding.jsx are also unused.
